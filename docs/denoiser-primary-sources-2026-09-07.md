# Responsive Minecraft denoising: primary-source research

Research date: 2026-09-07. This note records the literature research before implementation. Its proposals are not measured speedups. The subsequent RELAX-style implementation and measured tradeoffs are in [the validation report](denoiser-validation-2026-09-07.md), and implemented commands are in [the game-test guide](denoiser-game-test.md).

## Recommendation

For the existing many-light ReSTIR diffuse signal, the strongest first experiment is **RTXDI's replay-based lighting-change confidence, feeding a smaller diffuse-only filter with RELAX-style statistical history clamping**. Preserve separate temporal state for direct light and GI so direct shadows can react quickly while noisier GI accumulates longer. Use Minecraft edit events to give immediate confidence loss on affected receivers; use sparse replay gradients to catch changes that geometric reprojection cannot see.

This is an engineering recommendation for this renderer, not a claim that one denoiser is universally fastest or highest quality. RELAX is an appropriate production reference for ReSTIR signals; a full NRD port is a much larger integration than borrowing its control ideas. A per-light shadow denoiser is especially attractive for a separate sun or dominant-light shadow signal, but cannot directly replace filtering of a sum of many RGB light contributions. [NRD overview](https://github.com/NVIDIA-RTX/NRD/blob/96e755db842b7cdc38fb67a0d5658dc8ad87364d/README.md), [RTXDI confidence design](https://github.com/NVIDIA-RTX/RTXDI/blob/a6efab966b7c3b272da0461578eb56ac61c7cbff/Doc/Confidence.md).

## What is current, and what can be reused

| Reference | Relevant signal and useful mechanism | Suitability here |
| --- | --- | --- |
| **NRD RELAX** | Diffuse/specular radiance; temporal histories and variance-guided à-trous filtering. Designed for RTXDI. | Best general denoiser reference for the current many-light signal. Specialize to diffuse; benchmark against the existing SVGF instead of importing every feature. |
| **NRD REBLUR** | Recurrent spatial blur; radiance/occlusion variants. | Alternative performance experiment, especially for GI. Its recurrent filtering and blur-radius control require careful sharpness testing. |
| **NRD SIGMA** | Per-light visibility, including translucent shadows. | Useful for a distinct sun/moon or selected dominant light. Penumbra-aware filtering is a better sharpness guide than receiver depth alone. |
| **AMD FidelityFX Shadow Denoiser** | Single-light shadow mask, at most one jittered ray per pixel; compact masks, tile classification, temporal clipping, small spatial passes. | Smallest practical source reference for a dedicated shadow path. It does not accept arbitrary RGB ReSTIR irradiance. |
| **A-SVGF / RTXDI confidence** | Detect shading changes through comparable sample replay. | The most directly relevant mechanism for reducing shadow lag without globally shortening all history. It complements a denoiser. |

NRD's [signal declarations](https://github.com/NVIDIA-RTX/NRD/blob/96e755db842b7cdc38fb67a0d5658dc8ad87364d/Include/NRDDescs.h), [RELAX spatial filter](https://github.com/NVIDIA-RTX/NRD/blob/96e755db842b7cdc38fb67a0d5658dc8ad87364d/Shaders/RELAX_Atrous.cs.hlsl), and [REBLUR settings](https://github.com/NVIDIA-RTX/NRD/blob/96e755db842b7cdc38fb67a0d5658dc8ad87364d/Include/NRDSettings.h) establish the signal and filtering distinctions above. AMD's contract and pass organization are documented in the [FidelityFX Denoiser 1.3 manual](https://gpuopen.com/manuals/fidelityfx_sdk/techniques/denoiser/). The temporal-gradient principle comes from [Schied, Peters and Dachsbacher, 2018](https://momentsingraphics.de/Media/HPG2018/Schied2018-AdaptiveTemporalFiltering.pdf).

Version distinction matters: the live GitHub API reported **NRD v4.17.3** as the latest published release, dated 2026-04-30. The inspected development head identifies itself as **v4.18.0**, commit `96e755db842b7cdc38fb67a0d5658dc8ad87364d`, dated 2026-09-07. The links in this note pin that development snapshot; they do not imply a released 4.18 package. [Latest-release API](https://api.github.com/repos/NVIDIA-RTX/NRD/releases/latest), [inspected commit](https://github.com/NVIDIA-RTX/NRD/commit/96e755db842b7cdc38fb67a0d5658dc8ad87364d).

NRD's listed integrations target D3D11, D3D12 and Vulkan. It has no documented ready-made OpenGL integration. Its source is under the **NVIDIA RTX SDK license**, as are RTXDI's sample gradient shaders; these should not be described as MIT code. Direct source reuse must retain the applicable license and notices. This note recommends techniques rather than making a licensing-compatibility determination. [NRD license](https://github.com/NVIDIA-RTX/NRD/blob/96e755db842b7cdc38fb67a0d5658dc8ad87364d/LICENSE.txt), [RTXDI license](https://github.com/NVIDIA-RTX/RTXDI/blob/a6efab966b7c3b272da0461578eb56ac61c7cbff/LICENSE.txt).

AMD's SDK `v1.1.4` contains **MIT-licensed denoiser source**, including GLSL callbacks. Those callbacks use Vulkan-style descriptor sets and separate texture objects, so OpenGL still needs binding and shader adaptation. The source's optimized shadow-filter path also uses FP16 helpers; do not assume every supported OpenGL GPU accepts that implementation unchanged. [SDK license](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/blob/v1.1.4/sdk/LICENSE.txt), [GLSL callbacks](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/blob/v1.1.4/sdk/include/FidelityFX/gpu/denoiser/ffx_denoiser_shadows_callbacks_glsl.h), [filter source](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/blob/v1.1.4/sdk/include/FidelityFX/gpu/denoiser/ffx_denoiser_shadows_filter.h).

## Closest implementation already in `/reference`

The most useful local reference is [RTXDI's confidence note](../reference/repos/RTXDI/Doc/Confidence.md), with three small stages in `Samples/FullSample/Shaders/DenoisingPasses`:

1. [ComputeGradients.hlsl](../reference/repos/RTXDI/Samples/FullSample/Shaders/DenoisingPasses/ComputeGradients.hlsl) selects a representative pixel within a stratum and re-evaluates the same light sample at a corresponding surface in the other frame. It uses stable light mapping and the saved light UV, disables visibility reuse for that comparison, and matches stored luminance precision to avoid false gradients. [Pinned upstream source](https://github.com/NVIDIA-RTX/RTXDI/blob/a6efab966b7c3b272da0461578eb56ac61c7cbff/Samples/FullSample/Shaders/DenoisingPasses/ComputeGradients.hlsl).
2. [FilterGradientsPass.hlsl](../reference/repos/RTXDI/Samples/FullSample/Shaders/DenoisingPasses/FilterGradientsPass.hlsl) smooths luminance differences and luminance scale separately using a small à-trous kernel. Do not treat the guide blur as permission to blur irradiance by the same radius. [Pinned upstream source](https://github.com/NVIDIA-RTX/RTXDI/blob/a6efab966b7c3b272da0461578eb56ac61c7cbff/Samples/FullSample/Shaders/DenoisingPasses/FilterGradientsPass.hlsl).
3. [ConfidencePass.hlsl](../reference/repos/RTXDI/Samples/FullSample/Shaders/DenoisingPasses/ConfidencePass.hlsl) normalizes the difference, adds a dark-region floor, and applies a short temporal filter that retains low confidence longer. This prevents a single noisy frame after a lighting transition from dominating newly restarted history. [Pinned upstream source](https://github.com/NVIDIA-RTX/RTXDI/blob/a6efab966b7c3b272da0461578eb56ac61c7cbff/Samples/FullSample/Shaders/DenoisingPasses/ConfidencePass.hlsl).

**Critical simplification:** without a previous-frame geometry snapshot, replay only the **previous sample in the current scene**. Replaying a current sample against the old frame requires that old scene. RTXDI explicitly states this limitation. RNG replay alone is inadequate for ReSTIR because reservoirs and light-list changes alter sample selection. [RTXDI confidence design](https://github.com/NVIDIA-RTX/RTXDI/blob/a6efab966b7c3b272da0461578eb56ac61c7cbff/Doc/Confidence.md).

Proposed specialization: retain a small, dedicated replay record with the previous primary point, stable emitter identity, emitter UV, previous evaluated luminance and necessary estimator multiplier. Re-evaluate that same record with fresh current visibility. Use its change only as a denoiser hint; it is not a reusable lighting reservoir. Existing splatting records may supply some fields, but their lifetime and jitter domain must be checked before sharing storage.

This keeps denoiser confidence independent from the separate correctness conditions of reservoir resampling. An invalid old reservoir may remain a useful **comparison record** without becoming a valid sample for current-frame MIS. The existing conservative global reservoir reset must not simply be removed as part of this denoiser experiment; the [local temporal contract](../reference/research/reservoir-splatting-temporal-contract.md) and [integration audit](rendering-audit-2026-09-07.md) explain the renderer's estimator constraints.

The original A-SVGF paper uses sparse, forward-projected samples with the same random sequence to estimate temporal shading changes, then adapts accumulation per pixel. This explains why receiver-depth and normal tests alone are insufficient: a stationary floor retains identical geometry while an off-screen block changes its shadow. A plain difference between unrelated noisy frames also confuses noise with real change. [A-SVGF paper, Sections 3.1–3.5](https://momentsingraphics.de/Media/HPG2018/Schied2018-AdaptiveTemporalFiltering.pdf).

Sparse gradients are a confidence heuristic, not guaranteed coverage. They can miss thin shadows, previously unsampled light contributions, and newly appearing lights. For known block edits, the proposed event mask should override gradient confidence immediately and recover over a short measured interval. Do not copy a smooth temporal blend that delays the initial response to a known edit.

## Sharpness and reconstruction ideas to borrow

**Statistical fast/slow history control.** RELAX builds local statistics from its responsive history in YCoCg and clamps the longer history against those statistics. It also compares with current noisy neighborhood statistics for anti-lag. This is a more appropriate reference than a fixed per-channel multiplicative box around one fast-history pixel. Any local port still needs edge and colored-light tests because clipping can bias real bright samples. [RELAX history-clamping source](https://github.com/NVIDIA-RTX/NRD/blob/96e755db842b7cdc38fb67a0d5658dc8ad87364d/Shaders/RELAX_HistoryClamping.cs.hlsl).

**Reconstruct new history before trusting temporal variance.** Both vendored Falcor trees contain the older SVGF implementation. [SVGFFilterMoments.ps.slang](../reference/repos/CGNS/Source/RenderPasses/SVGFPass/SVGFFilterMoments.ps.slang) computes spatial moments for history shorter than four frames and boosts early variance. [SVGFAtrous.ps.slang](../reference/repos/CGNS/Source/RenderPasses/SVGFPass/SVGFAtrous.ps.slang) carries variance with squared weights and anchors the center sample. These are useful baseline mechanics, although their constants are not automatically optimal for Minecraft. The source files carry their own redistribution notices.

**Keep texture detail outside illumination filtering.** The vendored [SVGF reprojection pass](../reference/repos/CGNS/Source/RenderPasses/SVGFPass/SVGFReproject.ps.slang) removes emission and demodulates albedo before filtering; the final modulation pass restores the material contribution. Preserve this division in the native shaderpack contract. A sharpening pass cannot restore a shadow edge already destroyed by temporal or spatial averaging.

**Use a meaningful shadow guide.** SIGMA reconstructs penumbra extent, obtains a spatial radius from it, and reduces filtering when that extent is small. It also uses receiver geometry to avoid unrelated surfaces. This supports retaining crisp contact shadows while allowing genuinely soft distant penumbrae. It requires actual shadow-related data; receiver depth or a constant alpha is not a substitute. [SIGMA blur implementation](https://github.com/NVIDIA-RTX/NRD/blob/96e755db842b7cdc38fb67a0d5658dc8ad87364d/Shaders/SIGMA_Blur.cs.hlsl).

For a mixed many-light estimate, a selected light's occluder distance is a noisy guide that changes when the selected emitter changes. Never use selected light ID equality as an unconditional spatial barrier: adjacent reservoirs are intended to represent the same lighting integral even when they select different lights. A clean SIGMA-style penumbra signal is simplest when that light is filtered separately. This is an inference from SIGMA's per-light contract and the renderer's many-light estimator.

**Spend bandwidth where filtering is needed.** AMD stores 8x4 binary shadow samples in a 32-bit mask and classifies uniform neighborhoods to skip work. That exact packing is appropriate to one-light binary visibility. For RGB direct/GI signals, borrow tile classification and compact metadata, not binary encoding of radiance. [AMD algorithm manual](https://gpuopen.com/manuals/fidelityfx_sdk/techniques/denoiser/), [tile-classification source](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/blob/v1.1.4/sdk/include/FidelityFX/gpu/denoiser/ffx_denoiser_shadows_tileclassification.h).

The AMD filter uses 3x3 spatial kernels at strides 1, 2 and 4 with shared-memory caching. Its final shadow pass also applies a contrast remap; this deliberately changes the result and should not be transplanted into RGB irradiance as an energy-preserving operation. Benchmark caching and tile skips separately from quality-altering remaps. [AMD filter source](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/blob/v1.1.4/sdk/include/FidelityFX/gpu/denoiser/ffx_denoiser_shadows_filter.h).

## Minecraft-specific simplifications worth testing

These are proposed adaptations, not claims made by the papers:

- **Use explicit edits as a change signal.** Once an edit is represented in the current GPU scene, immediately invalidate both slow and fast denoiser history, moments and confidence where its lighting can change. A block's screen rectangle is insufficient: affected receiving surfaces can be far away or the blocker can be off-screen. Conservative sun extrusion or local-light shadow volumes are candidate receiver bounds; retain a fallback when coverage cannot be proven.
- **Treat the first changed frame and recovery separately.** Known edits need immediate rejection of old light, followed by a brief low-confidence period and extra samples or local spatial reconstruction. This avoids accepting a single dark/noisy sample as long-lived truth. Count response from the input edit as well as from the first GPU frame containing the edit, so scene-upload latency is visible.
- **Use a full-cube fast path.** Six geometric face directions and planar receivers permit cheap face-class and plane-consistency tests. Keep a generic path for stairs, slabs, fences, vegetation, entities and normal-mapped materials. Geometric normals define topology; shading normals may still contain intended lighting detail.
- **Avoid artificial block seams.** Denoising demodulated irradiance across adjacent coplanar full-block faces can be useful. Requiring identical voxel IDs for every spatial neighbor would restrict reuse and can expose a grid. Use face orientation, plane and compatible shading class; stronger identity checks are more appropriate for temporal correspondence.
- **Specialize to diffuse first.** Omit glossy-specular tracking, SH/SG storage, material lobe permutations and hit-distance reconstruction for probabilistically skipped lobes when the actual input has none of those features. Add special handling only where the native shaderpack requires it.
- **Separate direct, indirect and deterministic terms.** Keep current direct light at full resolution for block-edge shadows. Test a cheaper resolution/history budget for GI independently, with edge-aware reconstruction. Keep deterministic emission and any native sun-shadow term in their established composition paths.
- **Allocate work after edits.** Compare a brief increase in direct candidates or fresh visibility rays in affected tiles with additional whole-screen blur passes. A small ray burst may make short history usable; whether it wins depends on this voxel traverser's cost.
- **Use one-light shortcuts only when valid.** A hard directional sun shadow can be evaluated deterministically at pixel samples without stochastic area-light noise. Choosing a zero-size sun or point emitter changes the intended softness model; it is an optional lighting policy, not a free quality optimization. Real area-emitter penumbrae should remain soft.

The root audit reports that this branch already has global scene-generation denoiser resets and configurable fine-to-coarse passes; its Photon fixture already uses two passes. Therefore, “add any history reset” or “reduce five passes to two” alone is not the novel recommendation. The useful changes are better signal separation, more selective confidence, valid shadow guides and reconstruction appropriate to newly reset history.

## Sampling research is related, but not a denoiser replacement

The vendored [CGNS README](../reference/repos/CGNS/README.md) describes a 2026 method for selecting ReSTIR neighbors by geometric compatibility. Its primary research page reports lower error and temporal covariance for a small incremental cost. That is promising for producing a more denoiser-friendly input, not a new denoiser. Keep it as a separate A/B experiment, with raw-signal metrics. [CGNS primary publication page](https://research.nvidia.com/labs/rtr/publication/junkins2026compatibility/).

Likewise, [Reservoir Splatting](../reference/repos/Reservoir-Splatting/README.md) improves sample reuse by retaining exact prior primary hits; it does not itself determine image-history blending or spatial blur. RTXDI documents how over-correlated temporal reuse can look deceptively low variance to a denoiser and yield slowly changing blotches. Adding spatial reuse can improve that noise structure. This is why judging only the final image can misdiagnose an estimator problem as a denoiser defect. [RTXDI noise and bias guidance](https://github.com/NVIDIA-RTX/RTXDI/blob/a6efab966b7c3b272da0461578eb56ac61c7cbff/Doc/NoiseAndBias.md).

## Neural options and performance evidence

Current neural options should not be ignored when discussing SOTA, but they do not meet this project's present portability constraint:

- **DLSS 4.5 Ray Reconstruction** is a current neural option for GeForce RTX hardware. Its integration guide uses D3D/Vulkan objects. It is a possible future vendor-specific backend rather than a portable GLSL denoiser to copy. [NVIDIA release announcement](https://www.nvidia.com/en-us/geforce/news/gamescom-2026-dlss-4-5-ray-reconstruction-release-announcements-trailers/), [official integration guide](https://github.com/NVIDIA-RTX/Streamline/blob/main/docs/ProgrammingGuideDLSS_RR.md).
- **AMD FSR Ray Regeneration 1.2.0**, released 2026-06-23, is an ML denoiser distinct from FidelityFX's older analytic denoiser. The official requirements are RX 9000-series or later, DirectX 12 / Shader Model 6.6 and Windows 11. It is not a cross-vendor OpenGL solution. [AMD manual and requirements](https://gpuopen.com/manuals/fsr_sdk/techniques/denoising/).

Building a bespoke neural denoiser would additionally require a representative training/evaluation corpus, inference integration and failure testing for modded geometry/materials. No measurements gathered here justify that as the shortest path to responsive block edits.

The inspected NRD development README reports RTX 4080, native 1440p timings of **2.55 ms for combined diffuse+specular REBLUR, 3.25 ms for combined RELAX, and 0.40 ms for SIGMA shadow**, under its specified default settings and 3x3 hit-distance reconstruction. These establish an order of cost for that vendor test only. They are not diffuse-only timings, an equal-signal comparison with SIGMA, cross-vendor results, or predictions for this OpenGL renderer. [NRD benchmark conditions](https://github.com/NVIDIA-RTX/NRD/blob/96e755db842b7cdc38fb67a0d5658dc8ad87364d/README.md).

## Evidence needed before selecting an implementation

The accompanying `runShaderGameTest` work should compare the unchanged baseline with one change at a time: statistical history clamping; edit/replay confidence; DI/GI separation; shadow guide; then tile/caching optimization. Measure per-render-frame direct raw irradiance, denoiser temporal output, final denoised light and final shaderpack output. Record GPU scene-generation visibility alongside the edit's input time.

An informative acceptance target is **visible response in the first valid changed frame and approximately 90% of the final shadow step within three rendered frames**, with a separately reported input-to-GPU delay. This is a proposed benchmark target, not an established capability. Measure stationary noise and shadow-edge width against a converged reference too; fast response gained by persistent noise, dark bias or widened edges is not a win.

Use paired placement/removal, on/off lights, thin blockers, distant receivers, camera movement, colored glass and a distant redstone clock. Fixed-camera block edits are especially diagnostic because geometric reprojection can remain valid while lighting is wrong. GPU timer queries should isolate denoiser and tracing costs; screenshot readback should not be included in those stage timings. Publish the GPU, driver, resolution, shaderpack archive hash, branch snapshot and effective options with every comparison. No algorithm in this note has yet been benchmarked in this repository.
